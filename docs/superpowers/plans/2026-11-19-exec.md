# exec Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Three new kern modules, `exec`, `exec-coroutines` and `exec-test`, that start a child process on the JVM and
Linux native and hand back its output, exit and control, plus a local-only `exec-cli` for trying it by hand.

**Architecture:** `exec` holds the public types in `commonMain` and one `SystemStarter` per platform. Linux native
starts through a small C helper (fork, `setpgid`, exec, an error pipe) and reads with one `poll` loop over the two
pipes, a `pidfd` and a wake-up `eventfd`. The JVM runs `ProcessBuilder` on Java 17 to 21 and an FFM `posix_spawn` path
on Java 22+, the latter in the jar's `META-INF/versions/22` as `fs-coroutines` already does. `exec-coroutines` turns
the blocking `Child.next()` into a `Flow`; `exec-test` scripts children.

**Tech Stack:** Kotlin 2.4.21 Multiplatform, the `kern-module` convention, kotlinx-coroutines 1.11.0, kotlinx-io
0.9.2 (`Path`), cinterop C on Linux, `java.lang.foreign` on Java 22+, kotlin.test.

**Spec:** `docs/superpowers/specs/2026-11-19-exec-design.md` (item 10 in `todo.md`). Read it first; this plan does
not repeat its reasoning.

## Global Constraints

- kern never throws: every failure is a typed `ExecError` in a `Result` or a `ChildEvent.Failed`, an empty argv
  included. No `require`, `check`, `error()` or `TODO()` in main code.
- Targets: `jvm`, `linuxX64`, `linuxArm64` only, for all three modules. No stub targets.
- JVM bytecode 17 (`jdk-target`), built on JDK 25 (`jdk-build`); the FFM path compiles for 22 into
  `META-INF/versions/22`.
- Exit code: the status for a normal exit, 128+N for a death by signal N.
- Signal numbers (Linux): `Hangup` 1, `Interrupt` 2, `Quit` 3, `Kill` 9, `Terminate` 15.
- Never stop a child unless `stop` is called: not on cancel, not on drop, not on this process's exit.
- No cap on buffered output; no ceiling a caller cannot raise.
- Test names: backtick names with **no commas** (a comma fails every Kotlin/Native target).
- Every gate runs the metadata compile too: `./gradlew :<module>:check :<module>:compileLinuxMainKotlinMetadata`
  (per-target compiles accept what the commonizer rejects).
- Commit messages: `exec: ...` style as in `git log`, **no attribution trailers** (no `Co-Authored-By`).
- KDoc and READMEs written for consumers, per the `code-comments` skill: no internal phase names, no history.

## Review Focus

1. **A child that exits without reading its stdin bytes** must not kill this process with SIGPIPE: the writer gets
   EPIPE, drops the rest, and nothing is reported. Test in Task 3.
2. **Two children at once**: the first one's `OutputClosed` must come while the second still runs, so no pipe end may
   leak into another child (`pipe2(O_CLOEXEC)`, close-on-exec everywhere). Test in Task 3 and, for the JVM, Task 6.
3. **Output nobody reads yet**: a child writing 10 MiB while the caller has not called `next()` must finish and exit;
   all of it comes later, in order. Test in Task 3.
4. **argv passes through untouched**: spaces, quotes, empty strings and `*` reach the child as given, no shell. Test in
   Task 3.
5. **Program lookup**: a bare `argv[0]` is looked up by kern itself in the **child's** `PATH` (as the spec says), on
   both platforms; a child environment without `PATH` makes a bare name `ProgramNotFound`. A name with `/` is used
   as given, a relative one against the command's working folder. Test in Task 3 (the author's call: no hidden
   default path, and the JVM's own lookup in the parent's `PATH` is bypassed).

**Interfaces:**
- Consumes: Task 1 types, `Utf8Stream`.
- Produces: `internal fun lookUp(program: String, path: String?, workingDirectory: Path?): Result<String, ExecError>`
  (bare name: first executable regular file in `path` split at `:`, blank entries skipped; else `ProgramNotFound`;
  existing but not executable everywhere: `NotExecutable`). Test helpers: `fun Command.events(): List<ChildEvent>`
  (start, drain `next()` until null, fail the test on a start error), `fun List<ChildEvent>.text(stream: Stream): String`,
  `fun sh(script: String, vararg args: String) = Command(listOf("/bin/sh", "-c", script, "sh") + args)`.

C helper `int kern_exec_spawn(const char *path, char *const argv[], char *const envp[], const char *cwd, int stdin_fd,
int stdout_fd, int stderr_fd, int *error_out)`: `fork`; in the child only async-signal-safe calls: `setpgid(0, 0)`,
`chdir(cwd)` when given, `dup2` the three fds, reset SIGPIPE to default and unblock all signals, `execve`; on any
failure write `errno` and a step tag (chdir or exec) into a close-on-exec error pipe and `_exit(127)`. The parent reads
the pipe: empty means exec succeeded. Errno mapping: chdir ENOENT/ENOTDIR → `WorkingDirectoryMissing`; exec ENOENT →
`ProgramNotFound`; EACCES → `NotExecutable`; anything else → `StartFailed(argv, strerror)`. All pipes by
`pipe2(O_CLOEXEC)`.

Reading: one thread per child runs `poll` over stdout, stderr, a `pidfd_open(pid)` and an `eventfd` for wake-ups;
events go to a lock-and-condition queue that `next()` takes from. On `pidfd` readable: `waitid(P_PIDFD, ...)`, then
read both pipes until `EAGAIN` (they are non-blocking), deliver that output, then `Exited`. A pipe at EOF is closed;
both closed sends `OutputClosed`. `Stdin.Bytes` is written by a thread of its own that blocks SIGPIPE with
`pthread_sigmask`, treats EPIPE as the end, clears a pending SIGPIPE with `sigtimedwait` (zero timeout), and closes
the pipe.

**Interfaces:**
- Consumes: `lookUp` (Task 3) for the program path, `Utf8Stream`, `exitCodeOf`.
- Produces: `internal fun startWithBuilder(command: Command, program: String): Result<Child, ExecError>`, used by
  `SystemStarter` on every JVM until Task 6 routes Java 22+ elsewhere. `Capabilities.jvm.kt`:
  `signalsAnything = stopsGroups = Runtime.version().feature() >= 22`. Until Task 6, JDK 25 runs `startWithBuilder`

Approach: `ProcessBuilder(listOf(program) + argv.drop(1))` with the directory, the environment map edited per
`Environment`, stdin `/dev/null` or a pipe written by a thread. Two reader threads feed one `LinkedBlockingQueue`
through `Utf8Stream`s. Ordering: on `process.onExit()`, each reader is asked to report "caught up" once it has read
everything `available()` showed at that moment; `Exited` is queued after both report. `stop`: `Terminate` →
`destroy()`, `Kill` → `destroyForcibly()`, others → `SignalUnsupported(signal)`; a dead process → success.
`detach()` closes the queue to `next()` and sets the readers to drop. `IOException` from `start` maps by message as
little as needed: the pre-checks (`lookUp`, `workingDirectory` exists and is a folder) give the typed errors first, so
the remaining `IOException` is `StartFailed(argv, message)`.
